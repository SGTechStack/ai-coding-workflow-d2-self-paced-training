Eitri Agentic Dev Workflow

This tutorial is for developers looking to build AI engineering skills. A software development background is required. Without prior experience writing, testing, and shipping code, you will not be able to critically review and validate the code and artefacts the workflow produces. Eitri builds on Matt Pocock's agentic engineering framework, extending it with story dependency sequencing, issue quality gates, compliance reviews, architecture boundary enforcement, and a human-in-the-loop (HITL) self-steering implementation loop. This tutorial starts with the foundational concepts behind the workflow, walks through each Eitri skill and where it fits, and shows you how to inject your team's domain context, architecture standards, compliance policies, and coding best practices to ensure the skills operate according to your team's standards.

Why Matt Pocock's framework?
  • Specification-first, specification as authority: a dedicated skill interviews you to produce a complete specification before any code is written, and that specification remains the source of truth throughout. When code and specification diverge, the specification wins. This directly addresses intent drift, the root failure mode of AI-assisted coding.
  • Composable and lightweight: provides small, focused skills deployed only when necessary. Each skill is designed to prevent a specific AI coding pitfall (such as skipping tests or losing track of context) without imposing a heavyweight process or replacing your engineering judgment.
  • No toolchain lock-in: compatible with any AI coding tool (Claude Code, Cursor, Cline) and any team setup, without imposing fixed directory structures or workflow conventions.
  • Built around real failure modes: every workflow decision addresses the primary ways AI coding fails (ambiguity, intent drift, and poor handoff quality) and is grounded in decades of engineering practice, not theoretical best practice.

By the end of this tutorial, you will be able to:

  • Execute Matt Pocock's agentic workflow end-to-end — from wayfinding (breaking down large efforts into investigation tickets) and PRD synthesis, to ticket decomposition, TDD implementation, two-axis code review, and structured bug diagnosis
  • Explain the Large Language Model (LLM) mechanics that shape the workflow's design — context windows, the Smart Zone and Dumb Zone, context rot, the three memory stores (in-context, external, parametric), hallucination, and non-determinism
  • Understand the engineering disciplines applied throughout the workflow — prompt engineering, context engineering, the ReAct pattern and its failure modes, QRSPI (Questions → Research → Structure → Plan → Implement) front-loading, agent skills and progressive disclosure, Retrieval-Augmented Generation (RAG), and Model Context Protocol (MCP)
  • Apply the development principles that structure agentic work — HITL design, specification-first development, TDD as a machine-verifiable convergence signal, Architecture Decision Records (ADRs), tracer bullet development, living documentation, and multi-agent orchestration patterns
  • Invoke the right Eitri skill at each workflow step — from dependency orchestration and architecture boundary enforcement through compliance audit, issue quality gates, and the self-steering implementation loop
  • Configure the workflow for your team by injecting business domain requirements, architecture standards, compliance policies, coding best practices, and code review standards at the right phase, ensuring every skill adheres to your team's specific standards
  • Ship a working application directly from user stories — applying the complete Eitri Agentic Dev Workflow to transform raw requirements into production-ready code
